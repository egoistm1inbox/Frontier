## 2. Dedicated icon class

Files:
- `Engine/DisplayPresentation/IconArt.h`
- `Engine/DisplayPresentation/IconArt.cpp`
- `Engine/DisplayPresentation/IconSymbols.inc`
- `EngineContent/Icons/Manifest.json` and approved SVG assets

The class provides typed icon identifiers, explicit logical size/display scale, aspect-preserving placement, a bounded least-recently-used collection of completed rasters, immutable shared pixel ownership, explicit reload, and a diagnostic/visible substitute for missing, malformed or unsupported artwork. It accepts trusted shipped artwork, not arbitrary SVG uploads.

It returns **straight-alpha RGBA8 pixels only**. It does not create ImGui texture identifiers, upload images, or access a device. The CPU icon proof uses those exact pixels. Subsequent device presentation must upload the same bytes.

Numeric fixtures cover RGBA channel order, half transparency, transparent margins, non-square aspect fitting, clipping, gradient direction, Gaussian blur, high display scale, repeated-request reuse, bounded eviction, invalid requests, missing/malformed SVGs, unsupported effects and runtime/pixel ownership.

## 3. Visual proof and compatibility limits

![CPU icon proof against independent SVG reference](../Exhibits/Gallery/IconArt/IconArtSummary.png)

Left: an independent CPU SVG decode of the **exact approved asset**, at explicit 128-pixel resolution. Right: the C++ `IconArt` diagnostic raster. These are not React screenshots.

- `IconArtStrict.png`: all 151 assets at 24, 30, 48 and 96 pixels. Pink crosses identify rejected artwork.
- `IconArtDiagnostic.png`: the same sizes, explicitly labelled incomplete where unsupported SVG features are present.
- `IconArtComparison.png`: eighteen representative reference/ThorVG comparisons.
- `Compatibility.tsv` / `.json`: per-asset status, unsupported features and numeric pixel differences.
- `Fixtures/`: the pixel fixtures used by the C++ assertions.

Comparison measures premultiplied RGBA difference, including alpha. Admission requires no unsupported SVG elements, mean error ≤2%, and no more than 10% of pixels above the recorded difference threshold. **82 assets satisfy those checks.** Antialiasing varies between rasterizers; this is tolerance-based agreement, not byte equality.

**69 remain blocked**, principally for drop shadows, turbulence, displacement, compositing/colour filter primitives or font-dependent text. Sun, Moon and Local Fog visibly demonstrate why ignoring those features would be wrong. Even an unsupported icon with a small aggregate pixel error remains blocked in strict mode. No original artwork was silently simplified.

## 4. Dependency findings

ThorVG is declared in the requested repository but not pinned there as a gitlink. This proof pins **ThorVG 1.0.0** at `6715f99ac106b6d4587f384a78c59fe957cfd2a3`.

Its pristine initializer replaces global scalar new/delete in a way that conflicts with sized deletion under AddressSanitizer. The original failure is preserved. A narrowly staged correction removes only those global replacements; both release and sanitized proofs use that same correction. No sanitizer check was disabled.

The target's existing ThorVG CMake source list/macros do not match this upstream release. A reviewed software-build include and an **unapplied** target CMake patch are supplied under `Tools/Build/`. The patch was checked against the pinned target with `git apply --check`. The full device build and Windows dependency builder were not run.

Detailed analysis: [ThorVG lifetime and presentation audit](ThorVGIntegrationAudit.md).

## 5. Approved control mapping

[Read the C++ property mapping and gaps](ImGuiControlMapping.md).

Critical differences found:
- Sun direction is astronomically solved/read-only in C++; the web permits manual dragging.
- Cloud coverage needs %↔0–1 conversion, and altitude/thickness need km↔m conversion.
- Local volumes use **half-extents and Z-up**, and currently only support boxes. Other primitive/custom shapes need real CPU/shader support.
- Independent bake targets are not equivalent to the existing baked-sky-dome path.
- Mixed flare effects, twinkle, moon roll/pitch, unlimited size and reference collections need additional representation or binding.
- The current sheet has fixed group/property/option limits; several richer web menus cannot be copied into it unchanged.

## Reproduce

From this checkout, with `gh` authenticated, Python 3.11+, g++ supporting C++20, `ar`, Node and the pinned npm dependencies:

```bash
npm ci
python3 Exhibits/Workbench/IconArt/PrepareTarget.py
python3 Exhibits/Workbench/IconArt/RunBaseline.py
bash Exhibits/Workbench/IconArt/RunIconProof.sh
```

The original baseline can take several minutes. It compiles and renders multiple CPU scenes; allow it to finish rather than imposing a short command timeout.

Dependencies and build outputs stay under ignored `.cache/`; no dependency checkout or binary is committed. Source and required proof images are preserved at target-compatible paths on this session's existing branch. No other branch was checked out or pushed.

To integrate into the C++ repository later, copy the new `IconArt` sources, approved icon content, proof sources and reviewed build support; then review/apply `Tools/Build/Patches/IconArt-TargetCMake.patch`. Seat the exact ThorVG pin. Resolve the 69 blocked SVGs before switching the outliner to strict icon rendering. The preserved baseline must remain a before-reference, not be overwritten by later UI results.
