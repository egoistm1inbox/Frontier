# Texture — mask painting and authoring modes

> **Subsequent extension:** live material/decal order, automatic white Layer 0, actual baked mesh support and lit UV appearance are covered in [layer evaluation](texture-layer-evaluation.md). The mask workflow below is retained. **Digital Paint / Erase / Fill now works on layers and their masks** in Lit and packed UV view; see [digital brushes, channels and limits](digital-painting.md). Legacy imported Texture/Generator-source composition and PBR atlas export remain separate.

Implemented in the existing Texture workspace on **10 October 2026**. This extends the [native part / packed UV workflow](texture-parts-uv.md), not a second editor, mesh importer, material-stack compositor, or replacement for Baking.

## Using it

1. Select a layer or folder and **Add layer mask**, or select an existing mask row. Mask selection sets **Mask mode**; the **Material / Mask** preview buttons are independent of **Lit / Wireframe / UV / Texture** geometry views.
2. In Mask preview the teapot shows the selected mask as an unlit grayscale coverage field: white includes, black excludes. In UV / Texture the same field is rendered on the actual packed triangles, not on a synthetic plane or a gradient's XY thumbnail. Material preview returns to the existing rendered material (or the UV chart/decal artwork view, which is not a baked PBR atlas). **Wireframe** applies to the actual grayscale mesh too; the UV field remains filled even when an edit is rasterized while Wireframe is active.
3. **Face**, **UV Island**, or **Object** arms surface selection. Click the 3D teapot or its authoring UVs. **UV Tile** is available only in packed **UV / Texture** mode. The gold outline and selection readout identify the real target.
4. Choose **White / Black** ink, then **Fill selection** or **Paint mask**. Without a picked region a brush is scoped to the hit component; with a region it stays clipped to that region. **Clear** removes the selection constraint, not the painted records.
5. Brush **Size**, **Opacity**, and **Hardness** are independent mask settings. **0% opacity** persists exactly and neither a brush nor a region fill creates paint records or undo entries. Size is a radius in percent of one UDIM tile. On phones, **Brush settings** expands those controls without permanently consuming the canvas.
6. Mask painting works in **Lit**. Starting a brush gesture switches to Mask preview so the live draft is visible. A completed gesture adds one undo step, even when it is internally split at UV-chart boundaries. Escape (including after keyboard focus leaves the canvas), pointer cancellation, switching away from the window/tab, changing target/view, or a conflicting document edit discards the uncommitted draft and releases pointer capture. Only the gesture's owning primary pointer can modify/complete it; unrelated touch moves, releases, cancellations and lost-capture events are ignored. Native two-finger navigation cancels the draft before changing the camera.
7. Selecting the **Material / Paint / Fill layer row**, rather than its mask, sets and stores **Paint mode · state only**. No ordinary mesh/channel paint is deposited. Existing **Stamp / Transform** operations still enter the functional Decal mode.
8. Save `.texture.json` for portable mask records; undo/redo and device-local recovery use the same validated document/history as the other Texture operations. **Clear painted mask overlay** in the right inspector keeps the underlying Fill / Gradient / Colour mask; Reset also clears the overlay.

## Real selection scope

- **Face** is one indexed triangle of the built-in 20-segment authoring teapot (25,440 triangles). Selection and strokes carry its actual face index, not a screen rectangle.
- **UV Island** is one of the actual 32 disconnected packed Bezier-patch UV charts. It is not an entire tile or merely a box around a chart.
- **UV Tile** selects the hit component's authoring UDIM: Body 1001, Lid 1002, Handle 1003, Spout 1004. The original overlapping UV0 remains read-only for authoring.
- **Object** is one native component — **Body, Lid, Handle, or Spout**. Selecting/painting Lid does not select the whole teapot. These semantic components share the default specimen's parent transform; native material assignments use extracted part meshes. This is not a claim that the historical teapot patches form four watertight closed solids.

Selections use the same barycentric authoring UV lookup for 3D ray hits and UV-space hits. Region paths are unions of the actual triangles. Brush segments split when the pointer leaves the surface or crosses charts, rather than drawing spurious lines across atlas islands. Filtering/antialiasing can soften subpixel triangle edges at the preview resolution.

## Which mask is displayed?

- **Fill / Paint**: the actual black/white background plus any painted overlay.
- **Gradient**: the existing normalized object-sphere point field, sampled at real surface positions. Painting is non-destructive over that field. Invert, enable/bypass, and strength apply after painting.
- **Colour**: normalized sRGB matching of the selected layer's imported texture/generator source, repeated per authoring tile. Folder masks use a descendant source. Transparent source pixels are excluded. No source means an empty colour field, not a fabricated match against the final lit material. This is explicitly labeled **source RGB per UV tile, not shaded material**; the old source-pixel inspector preview is retained.
- **Selected decal used as a mask**: the selected component's real alpha/luminance projector, including UV/object-space placement, native target, opacity, and inversion. The preview isolates that component rather than displaying a union of all the owner's decal masks. The ordinary material renderer still uses its existing per-owner union / ancestor product rules.

Selected-mask preview is not the product of unrelated masks or material alpha mislabeled as a mask. Material coverage on native part materials and decals includes inherited painted masks alongside existing Fill / Gradient and stamp masks. Native coverage remains alpha/cut-out coverage; the later stack-evaluation extension reveals actual lower material/decal passes and the implicit white fallback, rather than inventing a painted source layer. For uncomposited source layers, the grayscale preview is authoring feedback, not a claim that their channels have acquired a UV compositor.

## Data, limits, and ownership

- Existing schema **`alloy.texture.v1`** and **1 MB** project-file limit are retained. Old Fill / Colour / Gradient documents do not grow paint records unless painted.
- An optional `mask.paint` stores **`uvSet: "teapot-part-udim-v1"`** and bounded declarative operations. `brush` records store region, UV pairs, value, radius, opacity, hardness. `region` records store real region identity, value, opacity. No executable user code, URLs, rasterized mesh-map stand-ins, or material channels are introduced.
- Per mask: **128 operations**, **512 points per segment**, **8,192 total points**, and **32 UV units of total brush-path length**. Finite numeric values, native IDs, packed-tile bounds, and face/component agreement are validated. The point/path budget bounds interpolation work as well as JSON size; overflow rejects a gesture/import, not a silently truncated mask.
- Renderer previews use a temporary **1024 × 256** mask field, i.e. **256 × 256 per UDIM**, and the existing GPU gradient / stamp evaluation. CPU inherited paint coverage uses a cached barycentric object-position lookup. These temporary resources are not stored as painted PBR maps or reused as audited baking outputs.
- Selected layer/mask, stored authoring mode, preview, selection tool, and brush settings recover from **`alloy-texture-authoring-v1`**. Surface-region selection itself is transient. The project data still uses **`alloy-texture-project-v1`**. Neither key clears existing projects, materials, patterns, stamps, or repaired React caches.
- Locked ancestors, hidden targets, missing/mismatched targets, and read-only source UVs cannot commit mask strokes/fills. A draft guards the expected mask and owning selection, so a late pointer release cannot overwrite a changed mask.
- Preview, coverage, targets, outlines, textures, and asynchronous tickets have explicit lifecycles. UV atlas drawing restores the renderer target/clear colour and shared material depth/wireframe/UV-uniform state with `try/finally`, including failed readbacks. Existing decal placement, transforms, material application/export, library overlay behavior, and Baking stay in the same runtime.

It does not require unrelated floor/shadow pixels to remain bit-identical across geometry-view transitions. Ordinary material painting remains **state only**; existing decals remain functional.
