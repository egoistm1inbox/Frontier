Sun-shadow trace — what the shade pass is paying for

SunVisibility() in SurfaceShade.frag · N rays / pixel / frame · ~7–14 ms, tracks camera

Now closest-hit

Each ray runs TraceTwoLevel, which finds the closest hit: it keeps tightening FarLimit and draining the BVH stack even after it already knows the point is blocked. On the shadowed side — the expensive side — it visits the entire subtree for an answer we throw away.

reads back only Hit.HitCondition (yes/no)
computes nearest triangle, distance, barycentrics — all discarded

Fix any-hit

An any-hit traversal returns true the instant it finds one triangle between the point and the light. No FarLimit tightening, no near/far ordering, no stack drain. The far occluder is never even tested.

returns bool occluded — that's the whole question
quality bit-for-bit identical visibility

Why it's free — and where it wins most

  • Both shadow consumers ask a pure yes/no: shade's SunVisibility and integrate's sun-shadow ray (SurfelIntegrate.comp).
  • Closest-hit is only needed when you want which surface + where. Shadows don't — occlusion is boolean.
  • The win scales with occlusion: a lit pixel exits fast either way, but a shadowed pixel is exactly where closest-hit drains the most stack — and any-hit cuts that to the first blocker.

Swap the shade's N shadow rays onto it first, measure, then wire integrate's sun ray. No temporal, no denoiser, no quality change.
